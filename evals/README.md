# 评测题库

`luoke-search eval <题库.json> --testbed <语料的上一级> --index .dev/<名字>` 跑一组有标准答案的题，出第一名、前五、前十命中率和 MRR，按题型分开列，列出没排第一的题。

格式（digup 的，原样能跑）：

```json
{"base": "~/DigUpTestbed/zh/corpus",
 "queries": [{"q": "租房合同里能不能养狗", "expect": ["pdf/租赁合同.pdf@2-2"], "tag": "pdf-page"}]}
```

- `base` 里的 `~/DigUpTestbed` 换成 `--testbed`（或 `LUOKE_SEARCH_TESTBED`）给的文件夹。
- `expect` 是 `base` 下的相对路径，任意一个排进前几都算；`@2-2` 是第 2–2 页（PDF、幻灯片），`@20-35` 是第 20–35 秒（录音、视频）。

**去掉弱的结果**（2026-11-09，同样的实验室主控，三组题 176 道：`photo-relevance.json`、`same-topic.json` 在 `.dev/testbed-same` 上，中文四个题库在 `testbed/zh` 上；有答案 128、没答案 48）。起因是「护照照片」：护照的两张图后面跟着登机牌的照片（z 1.51，余弦 0.631），因为问题说了"照片"，照片的意思门槛从 z 2 放到了 z 1。规则：

- 只靠意思对上的（字词不到一半），z ≥ 2；问题点了录音、视频时这两类还是 z ≥ 1（10-21 定的那条），照片不再放宽；
- 而且余弦 ≥ 0.62（只对 `embeddinggemma-2/1`，别的向量空间量过以前没有这条）；
- 分数不到第一名一半的去掉，字词全中的不去；每个来源的条数跟着少；只在用上了意思时去（没向量、只按字词搜时没量过，不去）；
- 「找相似的」：余弦 ≥ 0.62。

| | 对的结果留下 | 错的结果 | 有答案、第一条对 | 没答案、什么都不给 |

| 以前（`--no-cutoff`） | 147 | 528 | 116 / 128 | 1 / 48 |
| **现在** | **146** | **193** | **116 / 128** | **12 / 48** |

- 丢的那 1 条是「护照照片」的第五条：卡通证件照（z 1.02，余弦 0.611）。前一名、前五名的成绩不变。
- 挑的时候看过：只靠意思对上的对的结果，余弦最低 0.632（截图）、0.636（录音）、0.657（文字）；错的中位 0.63 上下，分不干净。门槛按"有答案的题一道都不丢第一个对的"挑，余弦 0.63 也行，0.62 留一点余地。
- 没答案的题还剩东西的，多是近似的（「身份证照片」→ 护照的图和笔记，「猫的照片」→ 动物园里 z 2.02 的一张）和录音、截图（「长颈鹿」「生日蛋糕」第一条常是一段录音）。
- 「找相似的」用同一个文件夹算对（同主题语料里一个文件夹一个主题，粗）：118 条起点，余弦 ≥ 0.62 留下同文件夹的 99%，去掉别的 30%。条目和条目比的余弦比问题和条目高，加相对的门槛（不到第一名的几成）会丢同文件夹的，没加。

```bash

  --index .dev/<testbed-same 的索引> --testbed "$PWD/.dev/testbed-same"
```

**很有把握**（2026-11-09，同样的实验室主控、同样的 176 道题）：结果上的 `strong` 原来是"分数到这次第一名的一半"，相对的。去掉弱的结果以后，留下的几乎都过了一半，337 条里 335 条都是 strong，没有用处。窗口的全局搜索要把各个应用的 strong 放在一起（顶上「最相关」），所以改成看这一条自己：

- 要找的字都在名字里：文件名（不算扩展名和上面的文件夹，它们和文件名在同一个索引段里）、照片的标题；
- 或者它最像的那一段意思突出（z ≥ 2），而且余弦过门槛：文字 0.72、图片 0.70、声音 0.74（只对 `embeddinggemma-2/1`；别的向量空间量过以前，只有名字那条）。

一共 337 条结果、144 条对的（两次跑出来的结果条数差一两条，表里是最后一次）。

- 余弦按类型分开，因为对的、错的分开的地方不一样：图片 0.70 时 71 条里对 60 条；文字要到 0.72 才差不多；声音的 41 条里只有 3 条对，0.74 以下几乎都是错的。
- 名字那条错的 3 条：「钢琴的照片」「姜饼人的照片」「拍的那张发票照片」，文件名对上了，可题目要的是照片。文件夹名原来也算，「证件照」会让「证件」文件夹里的每张图都算 strong，审查发现后改成只看文件自己的名字。
- 只按时间、类型列出最新的那些（没有问的字），不算 strong。
- 改这个不动排序：中文题库照旧第一名 0.90、MRR 0.93。
- **局限**：门槛是在这 176 道题上挑的，数字偏乐观；英文和多语言没量；声音的数据很少。

量法：`eval … --hits` 每条结果多打了 `name_share`（名字里有几成要找的字）和 `strong`。

**英文和多语言**（2026-10-21，同样的实验室主控，`.dev/testbed-en`）：英文 **0.86 / 0.92**，孟加拉文和阿拉伯文 **0.75 / 0.94**，新写的有答案的那批 0.97 / 1.00。同样的索引换回 B-02 之前的打分（`eval --scoring a`，见下）是 0.97 / 1.00、0.92 / 0.98、0.94 / 1.00。上面 digup 的英文和多语言成绩只建了 `synthetic/`、只算答案都在 `synthetic/` 下的 31、43 题（螺壳内部的 DigUp 改版的 `luoke/scripts/en_eval.sh`）；同样那几题，螺壳搜索现在是 0.84 / 0.90、0.84 / 0.98，B-02 之前的打分是 0.97 / 1.00、0.93 / 0.98。
